# 전국 교통정보 점검 — 2026-10-04

## 결론과 검증 경계

서울·경기를 벗어나는 것을 막는 버스 지역 제한은 없다. TAGO 공식 도시 목록을
사용한다. 그러나 정류장 검색 지원과 실시간 도착정보 지원은 서로 다른 조건이다.
지하철은 전국 장소 검색은 가능하지만 실제 도착정보 연결은 서울시 API뿐이다.
전국 모든 버스·지하철 알람이 완성되었다고 안내해서는 안 된다.

운영 `/api/bus/config`를 읽어 서울·경기·TAGO·서울시 지하철 키의 설정 여부가
모두 true임을 확인했다. 이는 승인·응답 품질·전국 적재 완료를 검증한 것이 아니다.
이번 변경은 로컬 코드에 적용했으며 운영 배포, DB 변경, APK 설치는 하지 않았다.

## 이번 보완

1. TAGO 정류장 도시 목록과 도착정보 도시 목록을 병렬로 대조한다. 검색 가능,
   실시간 지원 목록에 있음, 미지원, 확인 실패를 분리한다. 확인 실패를 미지원으로
   단정하지 않는다. 기존 TAGO 메타데이터 캐시를 재사용하며 실시간 API 호출 주기는
   바꾸지 않는다. 서울·경기 자체 제공처 연결은 유지한다.
2. 실시간 미지원 도시에서도 정류장 검색은 유지하고 검색 응답에 경고를 포함한다.
3. 자동 경로 비교의 방향 검증/도착정보 공유 키에 도시코드와 nodeId를 포함한다.
   타 지역의 동일 정류장·노선 ID로 다른 차량의 도착시간을 재사용하지 않는다.
4. 지하철 검색은 카카오가 노출하는 최대 45개(15개씩 3페이지)를 읽는다.
   전체 검색은 8초 이내로 제한한다. 중간 페이지 오류를 정상 완료로 숨기지 않는다.
5. 역명과 노선명의 경계를 분리해 ‘중앙역 부산 1호선’, ‘중앙역 동해선’,
   ‘사상역 부산김해경전철’ 같은 이름을 서울 노선 목록에 의존하지 않고 처리한다.

## 2026-10-13 — 비수도권 지하철 시간표 기준 알람 연결

대표 결정: 실시간 API가 없는 지역 지하철은 **공식 시간표 기준**으로 알람을 제공하고 화면에 "시간표 기준"으로 표시한다.

- `src/server/subway-timetable.mjs`: TAGO 지하철정보(역 검색·역별 시간표)를 공통 DB → 실시간 API 순으로 읽고 12시간 캐시한다.
  현행 게이트웨이 주소(`SubwayInfo/Get…`)가 실패하면 구 주소(`SubwayInfoService/get…`)로 한 번 더 시도한다.
- 요일 구분: 한국 날짜 기준 평일 01 / 토 02 / 일·공휴일 03. 공휴일 API 실패 시 요일만으로 판단하고 `holidayCalendarKnown:false`를 응답에 남긴다.
- 자정 이후 열차(00~02시, 24시 이상 표기)는 전날 운행일로 계산한다. 20시 이후에는 다음 운행일 첫차도 포함한다.
- 방향 선택: 상행/하행을 종착역 이름(예: "하행 · 다대포해수욕장 방면 · 시간표 기준")으로 보여 준다. 다음 역 정보는 시간표에 없으므로
  자동 경로 비교(all-routes)에서는 다음 역의 시간표와 출발 간격을 대조해 방향을 확인한 경우에만 사용한다.
- 같은 이름 역 보호: 노선명에 부산·대구·광주·대전·인천·김해 등 지역이 있으면 서울 실시간 API를 호출하지 않는다.
- 수도권 실시간 역은 기존처럼 서울시 API를 사용한다(응답에 `basis:"realtime"`).

### 운영 전 확인 필요
1. 공공데이터포털에서 **국토교통부_(TAGO)_지하철정보** 활용신청·승인 (버스 API와 별도 신청).
2. 실제 응답으로 부산·대구·광주·대전·동해선·김해경전철 각 1개 역의 노선명, 시간 형식(HHMMSS), 자정 이후 표기를 확인.
3. 시간표 기준 알람은 지연을 반영하지 못한다는 안내 문구를 앱 화면에 유지.
