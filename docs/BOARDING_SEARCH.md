# 탑승 지점 검색과 지도 확인

홈 → 출발지 → 버스 또는 지하철 → 이름 일부 검색 → 지도와 후보 선택 → 노선/방향 → 최종 확인 순서입니다.

- 이름 검색은 원문, 공백 정리, 앞부분 검색 순으로 후보가 나올 때까지 조회합니다. 모든 철자 오류를 자동 교정하는 기능은 아닙니다.
- 같은 이름의 반대편 버스 정류장을 하나로 합치지 않습니다. 공식 정류장 ID와 좌표를 보존합니다.
- 좌표가 없거나 지도를 불러오지 못하면 지도 확인 완료로 처리하지 않습니다.
- TAGO 기점·종점을 현재 진행 방향으로 단정하지 않습니다. 지도에서 도로의 어느 쪽인지 확인하고, 목적지 경로의 다음 정류장까지 확인해야 합니다.
- 지하철은 상행/하행(순환선 내선/외선), 다음 역 방면, 종착역, 일반/급행을 구별합니다. 지도는 역 위치이며 정확한 승강장 내부 배치도가 아닙니다.
- 지하철 경로는 선택 노선, 다음 역, 열차 종류가 일치해야 선택할 수 있습니다. 열차가 목적지 또는 환승역 전에 종착하는지도 확인하세요.

## 필요한 서버 설정

기존 `KAKAO_LOCAL_REST_API_KEY`는 역명 검색에, `KAKAO_JAVASCRIPT_KEY`는 지도 표시에 사용합니다. 카카오 지도 웹 도메인에는 실제 운영 도메인이 등록되어야 합니다.

지하철 방향과 실시간 도착정보에는 **별도 서울 열린데이터광장 키**가 필요합니다.

1. https://data.seoul.go.kr/dataList/OA-12764/A/1/datasetView.do 에서 ‘서울시 지하철 실시간 도착정보’를 확인합니다.
2. 서울 열린데이터광장 로그인 후 Open API 인증키를 발급받습니다. TAGO/서울 버스 공공데이터포털 키와는 별도입니다.
3. Vercel 프로젝트의 Environment Variables에 `SEOUL_SUBWAY_API_KEY`를 **Secret**, **Production**으로 등록합니다.
4. 재배포한 뒤 홈에서 지하철역을 검색하고 제공되는 방향을 확인합니다. 키 값은 채팅이나 저장소에 올리지 않습니다.

서울시 API가 제공하는 역·운행 시간만 지원합니다. 전국 모든 지하철 실시간 지원을 의미하지 않습니다. 키가 없거나 방향/도착정보가 없으면 해당 상태를 안내하며 임의 정보를 만들지 않습니다.

## 시간과 안전 기준

### TAGO 검색 장애 대응

- 정류장 이름 검색과 도시 목록 조회는 일시 통신 오류, HTTP 502/503/504, TAGO 01/04/99 오류에 한해 한 번 재시도합니다. 인증·승인·사용량 초과 오류는 재시도하지 않습니다.
- 한 페이지 요청은 두 번의 시도와 대기를 합쳐 기존 8초 예산 안에서 처리하며, 페이지 전체 조회의 15초 제한도 유지합니다. 인증 확인 시간은 이 제한과 별개입니다.
- 정상적인 정류장 검색 결과는 5분, 도시 목록은 1시간 동안 서버 인스턴스 메모리에서 재사용합니다. 최대 128개 항목이며, 같은 요청이 겹치면 외부 호출을 공유합니다. 서버 재시작이나 다른 인스턴스에서는 다시 조회합니다.
- 캐시는 인증키의 해시·서비스·도시·검색어로 구분합니다. 실패 응답이나 불완전한 페이지는 저장하지 않으며 만료된 서버 캐시를 자동으로 돌려주지 않습니다.
- 같은 조건을 다시 검색하다 실패하면 화면의 이전 목록을 유지하고 안내 문구를 표시합니다. 검색어나 지역이 바뀌면 기존 목록을 지웁니다.
- **실시간 버스·지하철 도착정보에는 이 캐시와 재시도 정책을 적용하지 않습니다.** 정류장 목록이 보여도 최신 도착정보를 확인하기 전에는 탑승 가능 여부를 판단할 수 없습니다.

도착 예정 초에서 공식 `recptnDt` 이후 경과 시간을 차감합니다. 2분 넘게 오래된 자료, 미래 수신시각, 출발 처리된 열차, 0초/누락된 예측은 알람 판단에 사용하지 않습니다. 집에서 역·정류장까지 이동시간은 제외합니다.
